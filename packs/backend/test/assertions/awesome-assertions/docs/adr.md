# Assertions: AwesomeAssertions

**Status:** Accepted (generated)

## Decision

Assertions use AwesomeAssertions (`total.Should().Be(42)`), whose failure messages name the expression that failed and
the reason given (`because:`). The test framework's own `Assert` is banned in test projects by the Banned API analyzer,
so there is one way to assert.

AwesomeAssertions is the community fork of FluentAssertions 7, under the Apache License 2.0, as is every version of it;
FluentAssertions itself is under a commercial licence from version 8 on. The version is pinned in
`Directory.Packages.props`.

## Consequences

- A test using `Assert` does not build.
- Tests generated by the other packs assert with AwesomeAssertions too: this pack defines the assertions of the
  generator's test vocabulary.
- `tests/Assertions/AssertionExtensions.cs` adds two things: `Be` on a sequence, which is AwesomeAssertions' `Equal`
  (the same items in the same order), and `.Value()`, the value an assertion returns (the single item, the value as a
  type, the exception thrown), as a method, so the assertion stands as a statement as well as goes on as a value;
  AwesomeAssertions' own `Which` is a property.
- `Throw<T>()` and `ThrowAsync<T>()` also accept an exception derived from `T`; use `ThrowExactly<T>()` where the exact
  type matters.
