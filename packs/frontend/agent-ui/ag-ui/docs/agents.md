## Agent UI: AG-UI

{{~ if project["backend.topology"] == "services" ~}}
- With services, the browser talks to agents through the edge's `POST /agents/{name}`, which forwards the run to the service that owns the agent: that service speaks AG-UI at `POST /<module>/agents/{name}` (`src/Host/Wiring/AgentUiEndpoints.cs`) and lists its agents' names at `GET /<module>/agents`. The edge reads every service's list once at startup{{ if project["backend.auth"] != "none" }}, with a client-credentials client of its own (`EdgeClient:*`, which the AppHost sets){{ end }}, and never speaks AG-UI or runs an agent. Never add another AG-UI endpoint, in a module, a service host or the edge, and never reference Agent Framework's AG-UI hosting (`Microsoft.Agents.AI.Hosting.AGUI*`); `AgentUiGoesThroughAQuery` fails the build.
{{~ else ~}}
- The browser talks to agents through one host endpoint, `POST /agents/{name}`. Never add another AG-UI endpoint, in a module or the host, and never reference Agent Framework's AG-UI hosting (`Microsoft.Agents.AI.Hosting.AGUI*`); `AgentUiGoesThroughAQuery` fails the build.
{{~ end ~}}
- To offer an agent to the panel, add a query record in the module's Application project under `Queries/<UseCase>/` implementing `IAgentConversation<TSelf>`: `public static string AgentName => "<lower-kebab-name>";` and `public static TSelf Start(IReadOnlyList<ChatMessage> messages, JsonElement? state) => new(messages, state);`. Its handler creates the agent (`Agents/`), runs it with `RunStreamingAsync(query.Messages, ...)` and returns `.AsChatResponseUpdatesAsync()` as a successful `Result`. Nothing else registers it.
- Agent names are unique across modules; {{ if project["backend.topology"] == "services" }}the edge refuses to start on a name two services list, and a service host on one two of its queries share{{ else }}the host refuses to start on a duplicate{{ end }}.
- `state` is the panel's, untrusted input: validate it before a tool or the model sees it.
- In the web app, a conversation is `<AgentPanel agent="<name>" />` from `@/agents/AgentPanel{{ if project["frontend.framework"] == "vue" }}.vue{{ end }}`; the `assistant` module's page shows it. Do not install CopilotKit; lint refuses it.
- `src/agents/connectAgent.ts` is the one exception to the API client's rule against hand-written calls to the backend: an AG-UI run is a server-sent event stream the generated client cannot make, so `POST /agents/{name}` stays out of the OpenAPI document, and `connectAgent` posts to `/api/agents/{name}` on `@ag-ui/client`'s `HttpAgent` and reads the stream itself{{ if object.has_key(project, "frontend.auth-client") }}, setting the `Authorization` header from `accessToken()` (`@/auth/accessToken`), the token `src/api/baseApi.ts` sends{{ end }}. Never write a second: talk to an agent through `connectAgent` or the panel. Outside `src/api/baseApi.ts` and `connectAgent.ts`{{ if project["frontend.realtime"] == "sse" }} (and the realtime stream's `src/realtime/connection.ts`){{ end }}, any reference to `fetch`, `XMLHttpRequest`, `Headers`, `HttpAgent` or `EventSource` fails lint, bare or through `window`, `globalThis` or `self`{{ if project["frontend.framework"] == "vue" }}, in a component's template too{{ end }}. Never reach one through a variable or a computed name to get past it: lint cannot see that, and the backend's policy, not lint, is what protects the host.
- Show what an agent says as text, never as HTML or Markdown rendered unescaped: its answer is untrusted input.
- Test an agent's query with `ToolCallingChatClient` (`tests/Fakes`), as `tests/Modules/Assistant.Tests` does. The integration tests and `.github/scripts/e2e.sh` answer through the host's stand-in model, switched on by the AppHost parameter `model-stand-in`; never set it outside tests, and never call a real model from a test. Test a panel against a stream you send yourself, as `src/agents/AgentPanel.test.{{ if project["frontend.framework"] == "vue" }}ts{{ else }}tsx{{ end }}` does.
