## Forms: FormKit

- A form is `<FormKit type="form" :actions="false" :value="{ ... }" @submit="submit">`, with an initial value for every field, holding `<FormKit type="text|textarea|select|..." name="..." label="..." />` inputs and the project's own submit button. Add layout classes {{ if project["frontend.styling"] == "css-modules" && project["frontend.ui-library"] != "vuetify" }}from the component's CSS module with `:form-class="styles.form"`, `:outer-class` and the like; do not style inputs one by one: their look is in `src/forms/formkit.config.ts` and `src/forms/formkit.module.css`.{{ else }}with `form-class`, `outer-class` and the like; do not style inputs one by one: their look is in `src/forms/formkit.config.ts`.{{ end }}
- Submit with `const submit = schemaSubmit(schema, handler)` from `@/forms/schemaSubmit`: `schemaSubmit(schema, handler)` puts the schema's messages on the fields and calls `handler(values, form)` only for a valid form, with the schema's output (trimmed, transformed). Refuse a value the schema cannot judge with `form.setErrors([], { field: ['message'] })`.
- Validate with the {{ if valibot }}Valibot{{ else }}zod{{ end }} schema only, never with FormKit's `validation="..."` rules. One schema per form, next to the form; reuse it for the API request type where they match. Do not install `@formkit/zod`, a FormKit theme, vee-validate or TanStack Form (lint refuses the libraries).
