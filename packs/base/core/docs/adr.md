# Base: an Aspire modular solution

**Status:** Accepted (generated)

## Decision

- **.NET Aspire is the composition root.** `src/AppHost` is the only place runtime resources are added; nothing wires a connection string by hand.
- **Modules are bounded contexts** under `src/Modules/<Module>/`, each split into Domain, Application, Infrastructure and Api projects.
- **Modules register by convention, never by list.** Builds find module projects by glob, the host finds each module's `IModule` by assembly scan, and per-layer packages come from `src/Modules/Directory.Build.props`. Adding a module adds files only.
- **One build for everything:** `build.proj` (Microsoft.Build.Traversal) builds every project under `src/` and `tests/`. `Solution.slnx` is for IDEs and lists the projects present at generation; after `fabric add-module`, run `dotnet sln Solution.slnx add` for the new projects.
- **One dependency-free kernel.** `src/Kernel` carries the building blocks every layer uses (argument guards, result and absence types, as chosen) and is referenced and globally imported by every project but the AppHost.
- **Warnings are errors**, with the recommended analyzers and code style enforced in the build. Package versions are managed centrally in `Directory.Packages.props`.
- **The code style is checked, not stated.** `.editorconfig` raises these rules to `warning` for `src/` and `tests/`, so the Release build fails on them: `var` wherever it compiles (IDE0007); collections declared with an explicit type and a collection expression (IDE0028, IDE0300–IDE0304; IDE0305, which would turn a closing `.ToList()` into a spread, stays off); file-scoped namespaces (IDE0161); braces on every block (IDE0011); namespaces that match the folder (IDE0130); `int`, not `Int32` (IDE0049); readonly fields where nothing reassigns them (IDE0044); and the naming rules (IDE1006): interfaces start with `I`, private fields are camelCase with no leading underscore, private constants and static readonly fields are PascalCase, and async methods in `src/` end in `Async` (test methods are sentences, async or not). `this.` is permitted where a constructor parameter shares a field's name, and required nowhere else. A naming rule's own severity is not read by `dotnet build`; `dotnet_diagnostic.IDE1006.severity` is what makes the build report it. IDE0049 comes from Roslyn's name simplifier, which runs in `dotnet format` and not in `dotnet build`: the CI format check is where it fails. Sections are scoped by path, never `[*.cs]`, because an editorconfig severity outranks a project's `NoWarn` and a blanket section would switch a rule back on where a project turned it off. Generated EF migrations are `generated_code`, so no analyzer reports on code `dotnet ef` would write again.
- **Formatting is checked, not reviewed.** `.github/scripts/format.sh` runs `dotnet format` over every project under `src/` and `tests/`; CI runs it with `--verify-no-changes` before it builds. `dotnet format` cannot read `build.proj` (it formats nothing and succeeds) and `Solution.slnx` misses modules added later, so the script lists the projects in a throwaway solution.
- **Architecture rules are code.** Each rule implements `IArchitectureRule` in `tests/Architecture.Tests`; the test framework runs all of them.
- **HttpClients retry only idempotent methods.** `AddServiceDefaults()` gives every HttpClient the standard resilience handler with its retry confined to the methods RFC 9110 calls idempotent: GET, HEAD, PUT, DELETE, OPTIONS and TRACE. A POST or PATCH that timed out after the server applied it would otherwise be sent again and applied twice; it gets one attempt, and keeps its timeouts and circuit breaker. A client whose POSTs or PATCHes are idempotent in fact (a token mint, where a second token supersedes the first) opts back in with `.RetryEveryMethod()` on its `IHttpClientBuilder`, which restores the retry of transient failures and nothing more. Retrying is what needs a reason, so the reason is written at the call site. Two architecture rules send requests through the real defaults against a failing server and count the attempts. What they cannot see is left to review: whether a `.RetryEveryMethod()` is justified, and an HttpClient the defaults never reach (one made with `new HttpClient()`, or given a resilience pipeline of its own).
