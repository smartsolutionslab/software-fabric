# Base: an Aspire modular solution

**Status:** Accepted (generated)

## Decision

- **.NET Aspire is the composition root.** `src/AppHost` is the only place runtime resources are added; nothing wires a connection string by hand.
- **Modules are bounded contexts** under `src/Modules/<Module>/`, each split into Domain, Application, Infrastructure and Api projects.
- **Modules register by convention, never by list.** Builds find module projects by glob, the host finds each module's `IModule` by assembly scan, and per-layer packages come from `src/Modules/Directory.Build.props`. Adding a module adds files only.
- **One build for everything:** `build.proj` (Microsoft.Build.Traversal) builds every project under `src/` and `tests/`. `Solution.slnx` is for IDEs and lists the projects present at generation; after `fabric add-module`, run `dotnet sln Solution.slnx add` for the new projects.
- **One dependency-free kernel.** `src/Kernel` carries the building blocks every layer uses (argument guards, result and absence types, as chosen) and is referenced and globally imported by every project but the AppHost.
- **Warnings are errors**, with the recommended analyzers and code style enforced in the build. Package versions are managed centrally in `Directory.Packages.props`.
- **The code style is checked, not stated.** `.editorconfig` raises these rules to `warning` for `src/` and `tests/`, so the Release build fails on them: `var` wherever it compiles (IDE0007); collections declared with an explicit type and a collection expression (IDE0028, IDE0300–IDE0304; IDE0305, which would turn a closing `.ToList()` into a spread, stays off); file-scoped namespaces (IDE0161); braces on every block (IDE0011); namespaces that match the folder (IDE0130), except in `src/**/Wiring/`, where wiring extension methods are declared in the `Microsoft.*` namespace they extend and which is the only place a `Microsoft.*` namespace may appear; `int`, not `Int32` (IDE0049); readonly fields where nothing reassigns them (IDE0044); and the naming rules (IDE1006): interfaces start with `I`, private fields are camelCase with no leading underscore, private constants and static readonly fields are PascalCase, and async methods in `src/` end in `Async` (test methods are sentences, async or not). `this.` is permitted where a constructor parameter shares a field's name, and required nowhere else. A naming rule's own severity is not read by `dotnet build`; `dotnet_diagnostic.IDE1006.severity` is what makes the build report it. IDE0049 comes from Roslyn's name simplifier, which runs in `dotnet format` and not in `dotnet build`: the CI format check is where it fails. Sections are scoped by path, never `[*.cs]`, because an editorconfig severity outranks a project's `NoWarn` and a blanket section would switch a rule back on where a project turned it off. Generated EF migrations are `generated_code`, so no analyzer reports on code `dotnet ef` would write again.
- **One type per file, named after the type.** StyleCop.Analyzers runs in every project with exactly two rules on, both at `warning`: SA1402 (a file holds one top-level type) and SA1649 (the file is named after its first type, a generic type by its plain name: `Result<TValue, TError>` in `Result.cs`). `stylecop.json` sets `topLevelTypes` to class, interface, struct, enum and delegate (records count as classes and structs), so SA1402 covers every kind and not only its default, classes. Every other StyleCop rule is off in the path-scoped `.editorconfig` section, one category at a time, plus SA0001, which belongs to no category and is named on its own. Only two cases are allowed: types nested inside another type, which are not top-level, and generated EF migrations, which are `generated_code`. A generic and a non-generic type with the same name, and bodiless declarations (`interface ICommand<TResult>;`, a positional record), get files of their own like any other type. StyleCop cannot exempt them by configuration, and an exemption that needs a suppression would be one more rule nobody checks.
- **Formatting is checked, not reviewed.** `.github/scripts/format.sh` runs `dotnet format` over every project under `src/` and `tests/`; CI runs it with `--verify-no-changes` before it builds. `dotnet format` cannot read `build.proj` (it formats nothing and succeeds) and `Solution.slnx` misses modules added later, so the script lists the projects in a throwaway solution.
- **Workflows pin actions to a commit and run once per ref.** Every `uses:` names a full commit SHA with its version tag in a comment, since a tag can be moved after review. CI has a concurrency group per workflow and ref that cancels a pull request's run when a newer push replaces it; a run on the default branch is never cancelled while it runs. The architecture rule `WorkflowActionsArePinned` reads the workflows as YAML and fails a step whose action is not pinned to a full commit SHA, a local action (`./...`) or a docker image by digest; it reads YAML rather than lines so that a step is found however it is spelled and a comment or a `run:` script that mentions `uses:` is not mistaken for one.
- **Dependabot keeps dependencies current.** `.github/dependabot.yml` has one entry per package ecosystem the project has, and none for an ecosystem it lacks: NuGet (`Directory.Packages.props`) and GitHub Actions (the pinned workflow steps) always, npm for the frontend workspace when one is generated. Each runs weekly; minor and patch updates are grouped into one pull request per ecosystem, and a major update comes on its own because it may need code changes. Its commits are `chore(deps): ...`, which the commit check accepts.
- **The time comes from `TimeProvider`.** Code that reads the clock directly cannot be tested against a chosen instant, so its time-dependent rules go untested and its tests compare against "now, roughly". `build/time/BannedSymbols.txt` bans `DateTime.Now`, `DateTime.UtcNow`, `DateTimeOffset.Now` and `DateTimeOffset.UtcNow` through the Banned API analyzer (RS0030) in every project but the AppHost, which composes processes and reads no time; tests included, since a test that needs the real clock can still say so with `TimeProvider.System`. `AddServiceDefaults()` registers `TimeProvider.System` (unless something registered a `TimeProvider` first), so anything the container builds takes it by constructor; Domain methods take the `TimeProvider` or the instant as a parameter. Every test project references `Microsoft.Extensions.TimeProvider.Testing`, whose `FakeTimeProvider` is set to an instant and advanced by the test. The BCL's own `TimeProvider` is used rather than a project-specific clock interface, because the framework's timers, caches and resilience pipelines already accept it.
- **New identifiers are Guid v7.** A random (v4) Guid lands anywhere in a B-tree index, so every insert keyed by one splits pages and scatters the index; `Guid.CreateVersion7()` is time-ordered, so new keys append. `build/ids/BannedSymbols.txt` bans `Guid.NewGuid()` through the Banned API analyzer (RS0030) in every project but the AppHost, which creates no identifiers. Tests are included: a test's Guid often becomes a stored key, and with one rule for the whole project nobody has to judge which Guids are "only data"; a test that needs a Guid takes `Guid.CreateVersion7()` like any other code. An identifier factory is `public static InvoiceId New() => new(Guid.CreateVersion7());`.
- **List queries are paged.** A list without a bound grows with the data until one request reads the whole table. `src/Kernel` carries the building blocks, so every module pages the same way and no query invents its own skip, take and answer: `Page` (counted from 1), `PageSize` (from 1 to `PageSize.Maximum`, 100; `PageSize.Default` is 20), `PagedResult<T>(Items, TotalCount, Page, PageSize)`, and `Sorting<TField>` with a `SortDirection`, whose field is an enum the query declares. `Page` and `PageSize` have no public constructor: `TryFrom` refuses a value outside the range, and `TryParse` binds a query string value, so an API binds them directly and refuses the rest before an endpoint runs. `Page.Maximum` keeps `page.Skip(pageSize)` an `int` at the largest page size. They return a `bool` rather than throwing or returning a result type, because the Kernel serves whichever guards, errors and absence options the project chose. Decided by the repository owner (2026-11-01): paging is required for collection queries behind a list endpoint; an internal lookup no endpoint answers with, a small fixed set, may return a plain list. The chosen API protocol says how a list endpoint takes paging and checks it. `tests/Kernel/Paging.Tests` keeps the Kernel's coverage.
- **Architecture rules are code.** Each rule implements `IArchitectureRule` in `tests/Architecture.Tests`; the test framework runs all of them.
- **HttpClients retry only idempotent methods.** `AddServiceDefaults()` gives every HttpClient the standard resilience handler with its retry confined to the methods RFC 9110 calls idempotent: GET, HEAD, PUT, DELETE, OPTIONS and TRACE. A POST or PATCH that timed out after the server applied it would otherwise be sent again and applied twice; it gets one attempt, and keeps its timeouts and circuit breaker. A client whose POSTs or PATCHes are idempotent in fact (a token mint, where a second token supersedes the first) opts back in with `.RetryEveryMethod()` on its `IHttpClientBuilder`, which restores the retry of transient failures and nothing more. Retrying is what needs a reason, so the reason is written at the call site. Two architecture rules send requests through the real defaults against a failing server and count the attempts. What they cannot see is left to review: whether a `.RetryEveryMethod()` is justified, and an HttpClient the defaults never reach (one made with `new HttpClient()`, or given a resilience pipeline of its own).
